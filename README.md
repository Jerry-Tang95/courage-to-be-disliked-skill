# 被讨厌的勇气 · Agent Skill

> "自由就是被别人讨厌。"
> —— 岸见一郎、古贺史健《被讨厌的勇气》第三夜

一个给 AI Agent 用的心理方法论 Skill：当你因为「别人会怎么看我」「怕被笑话」「不想得罪人」「等更完美了再开始」而退缩时，它帮你把**被讨厌**从「失败」重新分类为「行使自由的副作用」，并把人际关系的遥控器拿回自己手里。

---

## 一、它解决什么问题

人的很多「不敢」，表面是能力问题，底层是**认可欲求**——把「人际关系之卡」交给了别人，让别人怎么看我来决定我怎么活。

| 表面症状 | 底层机制 | 本 Skill 做什么 |
|---|---|---|
| 发个朋友圈反复删改最后没发 | 怕被评价「炫耀」 | 量化认可欲求占比，把「发不发」的决策权还给你 |
| 会上不敢提反对意见 | 怕得罪人 | 拿回人际之卡，给出表达边界的落地话术 |
| 产品打磨到「完美」才敢发布 | 等认可 = 求许可 | 戳破「等完美」是认可欲求的伪前提 |
| 习惯说「随便 / 都行 / 听你的」 | 长期压抑真实想法 | 识别迎合模式，练习把选择权握回来 |

**一句话定位**：它是一个**检测表**，不是鸡血。不给「要有勇气」这种裸话，只给可执行的下一步。

## 三、什么时候会自动触发

无需手动调用。当你的话里出现这些信号，Agent 会自行加载本 Skill：

**语言信号**

- 「别人会怎么看我 / 怕被笑话」
- 「我不想得罪人 / 不想被讨厌」
- 「等更完美了 / 等别人认可了再开始」
- 「被讨厌的勇气 / courage to be disliked」

**情境信号**

1. 想做一件事（转行、发内容、表达观点）但怕被同事 / 家人 / 前任笑话
2. 为迎合他人压抑真实想法，习惯说「随便」
3. 过度纠结评价，连穿什么、发什么都要先脑补别人反应
4. 总在等「更有权威了」再行动，本质是在求许可

## 四、使用说明与例子

### 例子 1：想发朋友圈但怕被说炫耀（正面触发）

**你说**

> 我想发条朋友圈分享我的作品，但怕同事觉得我炫耀，到底要不要发？

**Agent 会做**

```
第 1 步 · 检测认可欲求占比
「你这个'不发'的决定，有多少 % 是为了避免被同事讨厌 / 赢得他们认可？」
（引导你给出 0–10 的自评，通常落在 7–9）

第 2 步 · 区分性质
判断这是「行使自由的副作用」还是「真的会伤害人」。
→ 分享作品本身不伤害任何人，属于前者。

第 3 步 · 拿回遥控器
「发不发、发什么、什么时候发，由我定。有人觉得炫耀，那是他的课题。」
```

**关键输出**：一句不被认可欲求绑架的行动宣言 + 可选的落地话术（比如配文怎么写得不卑不亢）。

---

### 例子 2：会上不敢提反对意见（正面触发）

**你说**

> 我在会上不敢提反对意见，怕得罪领导和同事

**Agent 会做**

1. 识别认可欲求：把「被喜欢」置于「把事做对」之上
2. 拿回人际之卡：领导喜不喜欢你是**领导的课题**，你把意见说出来是**你的课题**
3. 给落地话术，而不是让你硬刚：

> 「这个方案我有个不同角度，可能不成熟，我说出来大家参考一下——」（先给台阶，再给内容）

---

### 例子 3：等完美了再发布（正面触发）

**你说**

> 等我把产品打磨到完美再发布吧，不然被用户喷怎么办？

**Agent 会做**

戳破伪前提：「等完美」本质是把发布权交给潜在批评者。被批评是行使自由的**代价**，不是停止行动的理由。然后给出 MVP 范围建议 + 预期批评的应对准备。

---

### 例子 4：不该触发的情况（会自动分流）

这些看起来像「不敢」，但**不是**本 Skill 的靶子，Agent 会转给相邻 Skill：

| 你说 | 为什么不是 | 转给谁 |
|---|---|---|
| 「搬来新城市三个月，谁都不认识，好孤独」 | 归属感缺失 ≠ 害怕被讨厌 | `community-feeling` |
| 「领导让我背锅，我该不该忍？」 | 这是划界 / 权力斗争问题 | `task-separation` / `decompete` |
| 「帮我写一份下周的项目周报」 | 纯任务委托 | 不调用任何 Skill |

### 例子 5：边界情况（会主动踩刹车）

**你说**

> 我被同事集体排挤孤立了，还要坚持做自己吗？

**Agent 不会**套用「被讨厌 = 自由」。在**毒性共同体**里，不被喜欢可能是真实的危险信号（排挤、报复）。它会先建议：自保 / 退出 / 寻求外部救济，而不是鼓励你硬扛。

**另一个边界**

> 我上次发言确实说错了，现在大家不爱理我，我要不要道歉？

这是**关系失能**，不是自由的代价。Agent 会引导你复盘自身行为、修复关系，而不是归因于「他们不理解我」。

## 五、工作原理

### 5.1 骨架：R-I-A-E-B

`SKILL.md` 按固定五段结构组织，这是 Agent 能稳定执行的根本原因：

| 段 | 作用 |
|---|---|
| **R** Reading | 一句原文锚定，防止方法论被漂移解读 |
| **I** Interpretation | 方法论骨架：定义 + 机制 + 关键澄清 |
| **A1** Past Application | 书中的应用案例（祖母的镜子、青年和上司） |
| **A2** Future Trigger ★ | **触发条件**：情境 + 语言信号 + 与相邻 Skill 的区分 |
| **E** Execution | **可执行步骤**：Agent 拿到后照做的 1-2-3 |
| **B** Boundary ★ | **熔断条件**：什么情况下不许用 |

`★` 标记的两段是激活质量的关键——A2 决定「该不该叫醒」，B 决定「叫醒后要不要踩刹车」。

### 5.2 激活链路

```
用户输入
   ↓
① Agent 扫描全部 Skill 的 description（frontmatter 里的自然语言）
   ↓
② 命中语言信号 / 情境信号 → 加载 SKILL.md 全文
   ↓
③ 先过 B（边界）：毒性共同体？真做错？把被讨厌当目标？
   ├─ 命中 → 熔断，转修复 / 救济 / 相邻 Skill
   └─ 未命中 → 继续
   ↓
④ 执行 E 三步：检测占比 → 区分性质 → 拿回遥控器
   ↓
⑤ 输出：一句行动宣言 + 落地话术（禁止裸用「要有勇气」）
```

### 5.3 三个核心设计

**① 量化而不是说教**
第一步永远是让用户打分——「这个决定有多少 % 是为了避免被讨厌」。把模糊的情绪变成可讨论的数字，避免 Agent 陷入空泛安慰。

**② 重分类：被讨厌是「证据」不是「目标」**
这是最容易被误用的一点，Skill 里反复澄清：

- ✅ 被讨厌 = 你按自己方针行动的**副作用**，是自由的**指标**
- ❌ 为了被讨厌而活 = 把指标当目的，故意惹人厌

**③ 有熔断机制**
边界段明确列出四种不适用场景，并承认作者原书的盲点：

- 毒性共同体 / 霸凌环境 → 先自保，不鼓励硬扛
- 真做错导致的冲突 → 修关系，不归因于「他们不理解」
- 把被讨厌当目标 → 明确违背自由本意
- 结构性不公 / 虐待 / 贫困 → 仅强调勇气可能让受害者内化压迫，应寻求制度性救济（这是原书的时代局限）

### 5.4 与相邻 Skill 的关系

```
        task-separation（课题分离）· 依赖
                  ↓ 划界之后
        courage-to-be-disliked（本 Skill）· 承受非议的勇气
                  ↓ 放下之后往哪投入
        community-feeling（共同体感觉）· 加法
```

- **减法 vs 加法**：本 Skill 是减法（放下认可欲求），共同体感觉是加法（自我接纳 / 他者信赖 / 他者贡献）。贡献而不图认可，需要被讨厌的勇气，所以二者常配对出现。
- **划界 vs 代价**：课题分离是「划界动作」，本 Skill 是「划界后招致非议时怎么扛」，二者几乎总配套。

## 六、测试

`test-prompts.json` 含 8 个用例，覆盖 3 类：

| 类型 | 数量 | 目的 |
|---|---|---|
| `should_trigger` | 3 | 该叫醒的时候必须叫醒 |
| `should_not_trigger` | 3 | 含跨 Skill 混淆诱饵，必须忍住 / 分流 |
| `edge_case` | 2 | 边界场景必须踩刹车 |

**盲测结果：8/8 通过（100%）**

测试方式是「独立 sub-agent 盲测」——不给它标注好的 type/expected，只给同书 9 个 Skill 的名称 + 描述作为候选池，模拟真实激活选择。这是防止「自我验证」的关键设计。详见 `test-results.md`。

复跑测试：

```bash
# 把 test-prompts.json 里的 prompt 逐条喂给一个未加载本 Skill 的 Agent
# 检查它是否选择了 courage-to-be-disliked
```
